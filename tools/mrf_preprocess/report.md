# MRF 背景抑制预处理：专利还原 + ARD-MAV 真实数据验证

> 参考：CN106335646A《一种干扰式反无人机系统》，说明书 S1 段（公式 (7)~(13)）的
> 「基于马尔科夫随机场的正则化图像预处理」。
> 代码：`tools/mrf_preprocess/`（纯 CPU / numpy + OpenCV）。所有数字均为本机实跑。

## 0. 结论（先看这里）

**不建议把 MRF 类背景抑制做成 YOLO26 的默认在线前处理。** 依据是 ARD-MAV 真实数据
（10 序列 × 250 帧均匀抽样，1860 帧 / 1860 个 ≤12 px 目标，其中 sky 596、urban 511、ground 753）：

1. **专利式 MRF 提升了"局部信噪比"，但没有降低误检。** 粗糙度残差类变体的 SNR 中位数
   为 1.2~2.0×（urban 最高 1.95×），但在建筑/地面背景下虚警反而上升
   （`FA@rec.5`：urban 139→518，ground 106→213）。局部环带 SNR 只看目标附近，
   而虚警来自全帧背景峰值——残差算子把背景纹理也一起放大了。
2. **在真正的痛点上（`rec@FA=1` 与 `FA@rec.5`），DoG(σ=1,3) 是最强基线**：
   `rec@FA=1` = 0.129 / 0.002 / 0.081（原图全为 0.000），
   `FA@rec.5` = 15 / 52 / 46（原图 69 / 139 / 106，降低 2~4.6×）。
   原图 `rec@FA=1` 在三个类上都是 0——**任何单一滤波都没有解决"高召回下全是误检"这个瓶颈**。
3. MRF 里唯一有竞争力的是 `mrf_flux(λ=1, radius=1)`：在**地面纹理**的极严格工作点
   `rec@FA=1` = 0.133（优于 dog 的 0.081），`FA@rec.5` = 86（优于原图 106），但 AUC/d′ 低于 DoG。
4. `mrf_gate`（专利"压背景、留目标"的直接实现）**整体中性偏负**：`FA@rec.5` 为 87/146/178
   （原图 69/139/106，地面变差 1.7×），且在低对比度天空序列上会吃掉目标
   （`gain<0.8`：phantom43 单序列 54%，三天空序列平均 21%）。
5. LCN 全面有害（SNR 0.30~0.85×，虚警最高），Top-Hat 中性且最慢（44 ms/帧）。
6. 量化友好性：`mrf_gate` 的直方图与 uint8 分布几乎不变（INT8 scale 1.979 vs 原图 1.980），
   可以直接进现有 INT8 流程；残差类输出只占 105~150 灰度（80% 码值空置），
   需要乘 gain 或按 int8 有符号直存，否则训练/量化会浪费动态范围。
7. 板端：x86 单核 P50 为 7~33 ms/帧（1080p），按 RK3576 A72×4 估算约 60~400 ms/帧，
   30 fps 不可行；只有 `mrf_res` / `mrf_res_r2`（两次 5×5 邻域均值）有 10~15 fps 的希望。

**如果要进前处理，推荐 DoG(σ1=1,σ2=3)，而不是 MRF**；更好的路径是把这个固定高通算子
放进检测器 stem（见 4.3），一次性训练解决，也不依赖板端在线预处理。

## 1. 专利的 MRF 预处理是什么，怎么落地成可实现的数学形式

### 1.1 原文核对（公式与三条性质）

专利在检测之前插入一级「正则化图像预处理」，目的不是识别，而是
**压低大面积同质背景、保留（相对增强）低对比度小目标**，让后级检测器面对的输入更干净。
其模型是一个 Gibbs 随机场：

```
P(X = x) = (1/Z) · exp(-U(x)),      U(x) = Σ_{c∈C} V_c(x)                 (Gibbs 能量)
```

- 势团 `c` 取二阶邻域（本文实现为 8-/4-邻域，半径 `radius` 可调，`radius=1` 即 3×3），
- 局部粗糙度（式 (10)，**有符号**）：

```
d_c x_{i,j} = -x_{i,j} + (1/(N-1)) · Σ_{(m,n)∈c-(i,j)} x_{m,n}
            = mean(邻域) - 中心像素
```

- 势函数（式 (11)）：`V_c(x_{i,j}) = ρ(d_c x_{i,j})`，
- 对 ρ 的三条要求（式 (12)(13) + 凸/单调/连续可微）：

```
(1)  lim_{t→0}   ρ'(t)/t = 0        # 小粗糙度（同质背景）→ 几乎不"复原" → 被压制
(2)  lim_{t→∞}   ρ'(t)/t = M ≥ 1    # 大粗糙度（目标边缘）→ 复原力度最大 → 被保留
(3)  ρ 单调递增、凸、连续可微
```

加上两条成像/优化式：

```
(7)  u = x - α·Kx                     # 相减式：背景估计 Kx 被减掉
(8)  J(u) = ½‖u - Kx‖² + α·J_a(x)     # 能量最小化（J_a 为 Gibbs 先验项）
```

专利原文明确指出：**同质背景粗糙度最小、目标边缘最大、背景自身的边缘介于两者之间**，
并称最终效果等价于"原始图像被一个各向异性滤波加权矩阵卷积"。

### 1.2 三条性质到底在说什么

把 `ρ'(t)/t` 看成该像素的**扩散系数 / 复原力度** `g(t)`：

- `g(0)=0`：完全同质的区域，能量项不惩罚"把像素替换成邻域均值"，即**背景被抹平**（相对压制）；
- `g(∞)=M≥1`：强粗糙像素（目标）被原样保留（M=1）甚至增强（M>1）；
- `g` 单调增：粗糙度越大越"舍不得动"，形成软门控。

这等价于一个**内容自适应**的各向异性卷积核：每一处的滤波权重 `g(d_c x)` 由该处图像自身决定；
固定一张图后 `u = x - α K x` 就是一次线性加权卷积，K 的元素即 `α·g`。

### 1.3 关键结论：经典 robust ρ 全部方向相反，不能直接套用

| ρ | `ρ'(t)/t`（=扩散系数 g） | t→0 | t→∞ | 符合专利？ |
|---|---|---|---|---|
| Huber | `1`（|t|≤δ），`δ/|t|`（否则） | 1 | 0 | ✗ |
| Charbonnier | `(1+u²)^(-1/2)` | 1 | 0 | ✗ |
| Tukey（截断二次） | `(1-u²)²`（u<1），`0` | 1 | 0 | ✗ |
| Geman–McClure | `(1+u²)^(-2)` | 1 | 0 | ✗ |
| **本节构造（atan 型）** | `1 - atan(u)/u`，u=t/τ | 0 | 1 | ✓ |
| **本节构造（指数型）** | `1 - exp(-(u)²)` | 0 | 1 | ✓ |

经典 robust 势函数是"**保边平滑**"：同质点强行平均、强边缘停止平滑——它保的是背景和边缘，
压的恰好是目标。**它只能用来估计背景（前向扩散），不能当作专利那个 ρ。** 这也是很多
"MRF 去背景"实现跑偏的地方：把 Tukey/GM 直接当 ρ，结果小目标被一起抹平。

### 1.4 两个满足三条性质的 ρ（本文实现，可切换）

**ρ_A（atan 型，与专利三条性质最贴合）**

```
ρ'(t) = τ · (u - atan u),   u = t/τ,   τ > 0
⇒ g(t) = ρ'(t)/t = 1 - atan(u)/u ∈ [0,1)
⇒ ρ''(t) = u²/(1+u²) ≥ 0        # 凸（t→0 时 →0，t→∞ 时 →1）
```

`t→0` 时 `g ≈ u²/3 → 0`；`t→∞` 时 `g → 1 = M`；`ρ(0)=0`，`ρ'≥0` 单调增，C^∞。
取 M=1 对应"保留"，需要更强增强时把输出乘增益 `gain`（专利允许 M≥1）。

**ρ_B（指数型，即 `w(d)=1-exp(-(d/τ)²)` 的势函数版本）**

```
ρ'(t) = t · (1 - e^{-u²}),  u = t/τ
⇒ g(t) = 1 - e^{-u²}
⇒ ρ''(t) = 1 - e^{-u²} + 2u² e^{-u²} ≥ 0    # 凸
```

同样满足三条性质，且在 τ 附近过渡更"软"，对小目标的保护更保守。

两者都实现了（`gate=rho` / `gate=exp`），实测差异见第 3 节；差异很小，**推荐用 ρ_B（exp）**，
因为它与"权重门控"的物理直觉一致、参数 τ 直接就是"多粗糙算目标"的尺度。

### 1.5 能量最小化怎么落到图像上

对式 (8) 求变分（`A` = 邻域均值算子，`I-A` 即邻域拉普拉斯）,取一阶近似：

```
∂J/∂u = (u - x) + λ (I - A) ρ'(d) = 0
⇒ u = x + λ (I - A) ρ'(d)                    # 实测变体 d：专利式 (8) 的不动点
```

这是**锐化**（把粗糙度回灌），M>1 的效果。而专利式 (7) 的 `u = x - αKx` 是**相减**背景，
对应实测变体 (b)。二者都写成"先估背景/先算粗糙度，再按 ρ 加权组合"，与专利末段
"各向异性加权矩阵卷积"的说法一致：

```
u = bg + g(d) · (x - bg)                     # 实测变体 (c)：本文主推形式
```

### 1.6 三种变体的对应关系（本文实现）

| 本文变体 | 数学形式 | 对应专利 |
|---|---|---|
| (a) 粗糙度残差 | `out = d_c x`（可选 `|d|` 或 `d·g(d)`） | 式 (10) 直接用 |
| (b) 背景相减 | `out = x - bg`, `bg` 由前向扩散估计 | 式 (7) `u = x - αKx` |
| (c) ρ 加权门控 | `out = bg + g(d)·(x - bg)` | 式 (11)+(12)(13) 的 ρ 作为权重 |
| (d) 能量不动点 | `u = x + λ(I-A)ρ'(d)` | 式 (8) 的固定点迭代 |

其中背景估计用的**前向扩散**（这才是经典 robust 权重的正确位置）：

```
b ← b + c(d) · (mean_neighbours(b) - b),    c = Tukey / Geman / Charbonnier 权重
```

`c(d)` 在大粗糙度处趋 0 → 扩散在目标边界自动停止，不会把目标扩散进背景。

## 2. 实现、参数与用法

代码在 `tools/mrf_preprocess/`：

| 文件 | 作用 |

`mrf_bgsub`/`mrf_bgsub_ms`、`mrf_gate`/`mrf_gate_ms`/`mrf_gate_rho`、`mrf_flux`、

| 参数 | 含义 | 建议 |
|---|---|---|
| `nbhd` | 4 / 8 邻域 | 8 |
| `radius` | 邻域半径：1=3×3，2=5×5，3=7×7 | 与目标尺度匹配：3~5 px→1，7~10 px→2~3 |

| `iters` | 背景扩散迭代 | 4~8 |

| `weight` | 前向扩散权重 | `tukey`（硬截断，目标不渗入背景） |
| `gate` | `exp`（ρ_B）/ `rho`（ρ_A） | `exp` |
| `polarity` | `signed` / `abs` | 训练用 `signed`（保留明暗极性） |

> 所以 gate 变体是单独用同一批 10×250 帧补跑的（命令：`--methods raw,mrf_gate_ms,mrf_gate_ms_tau16`）。

指标全部使用**同一个与模型无关的读数算子**（`D=|x−box_mean_11(x)|`，再 CFAR 式
`L=D/(box_std_31(D)+0.5)`），因此方法之间可直接比较：

- **SNR 中位**：GT 框内 `max|x−环带中值|` / 环带稳健 σ，逐目标算比值后取中位数；
- **gain<0.8**：目标对比度被抑制超过 20% 的比例（**"把目标一起抹掉"的直接量化**）；
- **AUC / d′**：GT 峰值（正）vs 全帧背景局部极大值（负）；
- **rec@FA=1**：每帧只允许 1 个假峰时的检出率（极严格工作点）；
- **FA@rec.9 / FA@rec.5**：达到 90% / 50% 检出率时每帧的虚假峰数（对应"降阈值全是误检"）；
- **P50/P95**：预处理本身耗时（不含读数算子），1920×1080。

| mrf_res_r3 | **2.20** | 1.54 | 1.81 |
| mrf_bgsub_ms | 1.36 | 1.14 | 1.37 |
| mrf_gate_ms | 1.03 | 1.05 | 1.07 |
| dog | 1.33 | 1.29 | 1.38 |
| tophat | 1.02 | 1.00 | 1.05 |
| lcn | 0.69 | 0.63 | 0.69 |
| mrf_flux λ=0.5 | 0.91 | 0.93 | 0.92 |
| mrf_flux λ=1 | 0.85 | 0.87 | 0.85 |

**尺寸结论**：邻域半径必须与目标尺度匹配——s≤6 px 时 `r=3`（7×7 邻域）SNR 最高（2.20×），
s10-12 px 时 `r=2/r=1` 更稳；而 `mrf_flux` 在**所有**尺寸档都 <1（0.85~0.93），
说明它是"锐化/高通"而不是"增强对比度"，它对小目标没有放大作用，靠的是压低背景峰值来获益
（与 3.2~3.4 的检测指标一致）。

### 3.6 参数敏感性扫描（τ / 迭代次数；小样本）

样本：phantom43(sky)、phantom56(urban)、phantom63(ground) 各 80 帧（有效 79/35/78）；
命令加 `--grid "mrf_gate_ms:tau=8,16"` / `--grid "mrf_gate_ms:iters=3,12"`，结果在
`sw_tau.md` / `sw_it.md`。方向与 3.2~3.4 的全量结果一致，因此可用于定参。

| 方法 | sky SNR | sky gain<0.8 | sky rec@FA1 | urban SNR | urban FA@rec.5 | ground SNR | ground FA@rec.5 |
|---|---|---|---|---|---|---|---|
| raw | 1.00 | 0% | 0.076 | 1.00 | 8 | 1.00 | 46 |
| gate τ=8, iters=6 | 0.78 | 54% | 0.076 | 1.14 | 8 | 1.08 | 45 |
| gate τ=16, iters=6 | 0.54 | 67% | 0.025 | 1.31 | 31 | 1.18 | 95 |
| gate τ=8, iters=3 | **0.93** | 42% | 0.089 | 1.12 | 8 | 1.08 | 45 |
| gate τ=8, iters=12 | 0.76 | 52% | 0.076 | 1.13 | 8 | 1.06 | 45 |

- **τ**：8→16 让 urban/ground 的 SNR 上升（1.14→1.31、1.08→1.18），但 `rec@FA=1` 全部下降、
  `FA@rec.5` 上升（8→31、45→95），天空甚至反向（0.78→0.54）。**τ 越大越"钝"**：
  门控把目标当成背景的比例上升（天空 gain<0.8 54%→67%）。推荐 τ≈8（目标对比度的 1/4~1/3）。
- **迭代次数**：3 / 6 / 12 对 urban、ground 的检测指标完全一致；天空在 iters=3 时 SNR 最好
  （0.93 vs 0.78/0.76），耗时 30 ms vs 37~39 ms。**iters=3 是性价比最高的设置**，
  说明背景只需粗估，多轮扩散只会把目标也吞进去。
- **半径**：见 3.5——`r ≈ 目标长边/3`，半径过大即"把 3~5 px 目标算进背景"。
- **`mrf_flux` 的迭代次数固定为 1**（它是锐化型，迭代会放大噪声，未做更多扫描）。

### 3.7 三条关键读数

1. **SNR 增益 ≠ 检测增益。** `mrf_res` 在 urban 的 SNR 1.95×，但 `FA@rec.5` 是原图的 3.7 倍。
   原因：环带 SNR 只看目标附近几十个像素，而虚警来自全帧背景局部极大值；残差算子对纹理
   背景的响应与 7~9 px 目标同量级，于是背景也变成"目标"。这是本次最重要的方法论结论。
2. **在召回痛点上，没有单一滤波解决问题。** 原图 `rec@FA=1` 三个类都是 0；
   最好的 DoG 也只有 0.129/0.002/0.081。滤波能把 `FA@rec.5` 降低 2~4.6×，
   但把 50% 召回时的每帧虚警压到"可接受"（比如 <5）还差一个量级。
3. **LCN 必须排除**（SNR 0.30~0.85×，`gain<0.8` 最高 80%，虚警最高），
   **Top-Hat 不值得**（几乎不改变可分性，44 ms/帧，是 DoG 的 3 倍耗时）。

## 4. 该不该进 YOLO26 前处理

### 4.1 明确建议

**不作为默认前处理。** 理由按优先级：

1. 真实瓶颈是召回，而 MRF 类方法在"高召回"工作点上并不比原图更好
   （urban `FA@rec.5` 139→154~518，ground 106→193~244）；
2. 最好的离线滤波（DoG）也只是把 `FA@rec.5` 降低 2~4.6×，不足以改判瓶颈；
3. 网络输入是 640×640：1920 宽的 7~9 px 目标在 letterbox 后只剩 **2.3~3 px**，
   信息损失发生在缩放这一步，**前处理无法补回**（这是推断，不是实测结论——
   实测只到"预处理后代理指标"这一层）。

如果仍要试，按场景分：

| 背景类型 | 建议 | 依据 |
|---|---|---|
| 平整天空 | **不建议**任何残差类前处理；如必须，用 DoG(σ=1,3) | 残差把噪声放大，`FA@rec.5` 69→87~137 |
| 建筑/复杂纹理 | 不建议（若有算力，DoG 作对照） | SNR 增益最大但虚警最差 |
| 地面纹理 | 可试 **`mrf_flux(λ=1, r=1)`** 或 DoG | 唯一在 `rec@FA=1` 上优于 DoG 的 MRF 变体（0.133 vs 0.081） |
| 未知/混合 | DoG，且只作为**额外通道**，不要替换原图 | 3.2~3.4 中 DoG 三项类全胜 |

### 4.2 推荐参数

| 变体 | 参数 | 适用 |
|---|---|---|
| `mrf_flux` | `nbhd=8, radius=1, lam=1.0, iters=1` | 地面纹理，极严格工作点；1080p 约 19~27 ms（x86） |
| `mrf_res_r2` | `nbhd=8, radius=2` | 7~9 px 目标；8~11 ms；只适合作为辅助通道 |
| `mrf_gate_ms` | `tau=8, iters=3, weight=tukey, scale=4` | 仅在有重训计划时用；**低对比度天空禁用**（会吃掉 54~67% 目标） |
| `dog` | `s1=1.0, s2=3.0` | 通用基线；13~18 ms |
| `mrf_bgsub_ms` | `tau=8, iters=6, scale=4, radius=1` | 不推荐（SNR 与虚警都不占优） |

`τ` 与尺寸的对应：本次只扫了 τ=8 / 16 两档（10×250 全量 + 早前 3 序列 × 60 帧 sweep，
两者一致）。τ 的物理含义是"多粗糙算目标"的门限，取目标局部对比度的 1/3~1/2 最合理：
7~9 px 目标的局部对比度实测在 20~40 灰度级，对应 **τ≈8~16**；τ 过大（目标对比度 < τ）时
门控会把目标判成背景，τ 过小则背景纹理全部被当目标（这点由 `gate` 的定义直接推出，
本次未单独扫 τ=4/32，不作实测声明）。
半径与尺寸的对应：**半径 r ≈ 目标长边/3**（3~5 px→r1，7~9 px→r2，10~12 px→r3），
该关系由 3.5 的尺寸分档数据支撑。

### 4.3 训练侧怎么接（不改训练脚本）

`make_dataset.py` 产出同构数据集 + `data-mrf.yaml`：

```powershell
& $PY make_dataset.py --src G:/0-rk3588/train/ARD-MAV/ARD-MAV-yolo `
    --dst G:/0-rk3588/train/ARD-MAV/ARD-MAV-yolo-mrf-flux `
    --method mrf_flux --set lam=1,radius=1
# 训练侧只需要： yolo train data=<dst>/data-mrf.yaml ...
```

实测成本（本机 x86，1920×1080，JPEG q95）：

- 生成速度 **0.42 s/图**（3 通道逐通道处理），全量 10761 张约 **75 min** 单核；
- 磁盘 **863 KB/图**（原图 611 KB），全量约 **9.3 GB**；
- 残差类输出需要 `--map signed`（+128 偏移），`mrf_flux` 用默认 `auto` 即可。

更省事的三条替代路径（都不需要改训练脚本，但都需要重训）：

1. **只换数据集**（如上），最简单的 A/B；
2. **原图 + 残差作为 3 通道**：`make_dataset.py` 目前是逐通道处理，要做出
   "R=raw, G=flux, B=flux_r2" 需要小改 `make_dataset.py`（约 10 行），未实现；
3. **把固定高通算子放进 stem**（推荐方向）：等价于把 DoG/MRF 变成一个不可学习的第一层卷积，
   一次训练、板端零额外预处理。**未验证，属于建议**。

### 4.4 INT8 / uint8 量化友好性（估算，`quant_check.py`，3 序列 × 40 帧）

| 方法 | uint8 clip<0 / >255 | p1~p99 | std | uint8 后 SNR 保留 | INT8 scale | INT8 RMSE(灰度) |
|---|---|---|---|---|---|---|
| raw | 0 / 0 | 16~244 | 70.0 | 1.000 | 1.980 | 0.56 |
| mrf_res | 0 / 0 | 105~150 | 6.5 | 0.996 | 0.344 | 0.08 |
| mrf_res_r2 | 0 / 0 | 90~166 | 10.9 | 0.989 | 0.588 | 0.15 |
| mrf_bgsub_ms | 0 / 0 | 88~167 | 11.6 | 0.989 | 0.629 | 0.18 |
| mrf_gate_ms | 0 / 0 | 17~244 | 69.7 | 0.995 | 1.979 | 0.57 |
| dog | 0 / 0 | 105~153 | 7.6 | 0.998 | 0.405 | 0.11 |
| tophat | 0.24% / 0.21% | 38~216 | 25.4 | 1.000 | 1.228 | 0.28 |
| lcn | 0 / 0 | 126~130 | 0.8 | **0.627** | **0.028** | 0.01 |

读法：

- **`mrf_gate` 与量化完全兼容**：直方图、std、INT8 scale 与原图几乎相同（1.979 vs 1.980），
  可以直接替换数据集而不用改量化流程；
- **残差类会把 80% 的 uint8 码值空置**（105~150 只用 46 级），SNR 保留仍 ≥0.989，
  但若直接存 uint8 等于浪费动态范围；建议乘 `gain=4~8` 再 clip，或按 int8 有符号存储
  （不要用 +128 偏移喂 int8 对称量化，否则零点偏移会吃掉一半精度）；
- **LCN 对 8bit 极不友好**：uint8 量化后只剩 0.8 个灰度的 std，SNR 损失 37%，
  INT8 scale 0.028（几乎全落在同一个量化格），这也是它实测最差的原因之一。

### 4.5 板端可用性（只做估算，未上板）

x86 单核 P50 实测 7~33 ms/帧（1080p）。RK3576 的 A72@2.2GHz 单核算术吞吐大约是
桌面 x86 单核的 1/8~1/12（内存带宽差距更大），按 4 核并行并假设 90% 并行效率：

| 变体 | x86 P50 | 板端估算 | 30 fps 可行性 |
|---|---|---|---|
| `mrf_res` / `mrf_res_r2` | 7~8 ms | 60~110 ms | 否（≈9~16 fps），与 NanoTrack 配合可接受 |
| `mrf_flux` | 19~21 ms | 160~280 ms | 否（≈4~6 fps） |
| `dog` | 13~14 ms | 100~160 ms | 否（≈6~10 fps） |
| `mrf_gate_ms` | 33 ms | 260~400 ms | 否 |
| `tophat` | 44 ms | 350~530 ms | 否 |

- **RGA 能做的**：降采样/格式转换（`scale=4` 的 INTER_AREA 可交给 RGA）、逐像素加减/加权混合
  （`bg + w·(x−bg)` 的合成），**不能做的**：邻域均值/卷积、形态学 Top-Hat、Gaussian。
  所以 RGA 只能帮 `mrf_bgsub_ms`/`mrf_gate_ms` 省掉 resize 和合成这两步，核心的 5×5 邻域均值
  还是得 CPU（可用 NEON 手写，两次分离式 box filter 即可）。
- 结论：**在线 30 fps 不可行**；若走"每 2~3 帧检测 + NanoTrack 跟踪"的现有架构，
  `mrf_res_r2`（≈10~15 fps）是唯一现实候选。

### 4.6 "抑制过强会把目标一起抹掉"的量化验证

用 `gain<0.8`（目标局部对比度被压低 20% 以上）统计：

| 变体 | sky | urban | ground |
|---|---|---|---|
| mrf_res | 25% | 4% | 4% |
| mrf_res_r2 | 21% | 2% | 4% |
| mrf_res_r3 | 12% | 1% | 4% |
| mrf_bgsub_ms | **38%** | 8% | 15% |
| mrf_gate_ms (τ=8) | 21% | 1% | 10% |
| dog | 24% | 4% | 10% |
| tophat | 39% | 23% | 32% |
| lcn | **80%** | 43% | **61%** |

- 风险最高的正是**平坦天空 + 强平滑类变体**：天空里目标几乎就是"唯一的局部异常"，
  一旦 `bg_smooth` 的 τ 相对目标对比度偏大，扩散会漫过目标本身。`mrf_bgsub_ms` 在天空
  压掉 38% 的目标；`mrf_gate`（τ=8）三序列平均 21%，但在**目标对比度最低的 phantom43** 上
  是 **54%**（`sw_tau.md`，n=79），τ 提到 16 进一步升到 **67%**。这不是均值问题，
  而是"低对比度目标 + 固定 τ"必然踩到的坑：τ 必须按序列/场景自适应，否则一定吃掉目标。
- **半径过大同样会吃掉目标**：`mrf_bgsub_ms` 用 `radius=2` 时天空 SNR 从 0.56× 掉到 0.43×
  （sweep2 实测，n=59），因为 5×5 邻域已经把 3~5 px 目标算进"背景"。

## 5. 局限（必须一起读）

1. **没有在预处理后的图像上重新训练。** 第 3 节所有指标都是无模型的代理指标；
   它们能说明"输入分布变干净了/变差了"，**不能**直接换算成 mAP 或召回收益。
   要得到可信结论，至少要用同一批数据重训 / 微调一次再比。
2. **指示性推理只说明分布漂移。** 用 `dwr_nwd_p2_e200/weights/best.pt`（imgsz=640，
   未在预处理图上训练）在 3 个序列各抽 20 帧做了对照（sky 20 帧、urban 13 帧、ground 20 帧）：

   | 类 | 方法 | det@conf.25 | det@conf.01 | GT 命中帧率 | 命中框置信度中位 |
   |---|---|---|---|---|---|
   | sky | raw / gate_ms | 0.7 / 0.7 | 7.3 / 8.2 | 0.900 / 0.900 | 0.162 / 0.294 |
   | urban | raw / gate_ms | 0.3 / 0.3 | 15.8 / 19.3 | 0.692 / 0.769 | 0.040 / 0.062 |
   | ground | raw / gate_ms | 0.1 / 0.1 | 6.3 / 6.8 | 0.250 / 0.250 | 0.011 / 0.004 |

   这些数字**只能说明**输入分布被改动（低置信度框增多、命中框置信度漂移），
   **不能当作精度结论**。而且该推理与另一并行训练任务共用同一张 GPU，时序不可作性能依据。
3. **样本覆盖有限**：10/60 个序列、1860 帧、每帧 1 个目标；≤6 px 只有 66 个目标，
   因此"3~5 px"的结论统计功效弱，主结论落在 7~9 px（918 个）。
4. **GT 来自 VOC XML**，与视频帧存在 ±1 帧对齐与框抖动风险；指标对框边界敏感
   （环带从外扩 4 px 起，已尽量避开目标溢出）。
5. **耗时是 x86 单线程实测**，板端为估算；未上 RK3576，也未测 RGA/NPU 实际占用。
6. **量化只做估算**：`quant_check.py` 用对称 per-tensor 模拟，未跑 RKNN 的真实混合量化，
   也没验证"预处理 + INT8 检测器"端到端掉点。
7. **参数网格不完整**：`radius` 扫了 1/2/3（全量），`tau` 扫了 8/16、`iters` 扫了 3/6/12
   （仅 3 序列 × 80 帧的小样本，`results/sw_tau.md` / `sw_it.md`）；`scale` 只用了 1 与 4，
   未做 2 的对照；`mrf_flux` 的 `lam` 只扫了 0.5/1。结论是趋势性的，不是最优点搜索。
